## Fallos iniciales y correcciones

1. En Windows, `pipeline.mjs` invocaba el ejecutable glTF Transform sin extensión y devolvió `ENOENT` para los ocho candidatos. La variante `.cmd` mediante `execFileSync` devolvió `EINVAL`. Se ejecuta ahora su JS fijado con `process.execPath`; el fallo no era del GLB.
2. La etapa `jpeg` del CLI falló con `colourspace: parameter space not set` en esta instalación: la dependencia transitoria `ndarray-pixels` resolvió `sharp` 0.35.5 mientras el pipeline fija 0.34.4. Para esta tanda, NodeIO + `sharp` 0.34.4 convierten directamente texturas opacas; conservan el perfil de salida y rechazan transparencia y extensiones desconocidas. No se alteró el lockfile ni la tanda #20.
3. El primer manifiesto producido en Windows contenía barras invertidas en `modelPath` y el validador excluía los seis modelos. Se normalizó la ruta generada a `/` y se repitió la prueba dirigida: 10/10.
4. La primera suite Node pasó 173/181. Los cuatro fallos de búsqueda y preview protegida comparaban 14/15 entradas o una búsqueda STOCKHOLM anterior a la nueva incorporación; se ajustaron a 20/21. La segunda pasada descubrió que `puf` coincide también con un genérico; la exclusión se prueba con `alhamn`, que no tiene ese sinónimo. Los cuatro casos F2 de exportación fallaron por `spawn python3 ENOENT`; la segunda pasada usa el shim temporal de Python 3.11 en `PATH`, sin cambiar el código F2.
5. El primer validador documental usó cp1252 en Windows y no pudo decodificar Markdown UTF-8. Se fijó `PYTHONUTF8=1`. El barrido posterior encontró la referencia a este informe antes de crearlo; se repetirá al cerrar.
