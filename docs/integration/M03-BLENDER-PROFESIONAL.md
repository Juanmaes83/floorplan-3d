# M03 · Blender profesional — candidata de integración

**Estado** · Candidata para Preview y aceptación visual. La fusión y Production requieren autorización independiente. Blender se ejecuta en el equipo de la persona mediante un kit incluido en la descarga.

## Recorrido real

1. Abre un proyecto y entra en **Escena 3D → Entregar → Documentación → Escena para Blender**. Pulsa **Preparar escena** y descarga el ZIP. Sirve también la ruta actual de Studio E3 hacia el generador de OP-10.
2. Descomprime el ZIP en una carpeta nueva y conserva su \`manifest.json\`. Ejecuta \`RENDERIZAR-windows.bat preview\` en Windows o \`sh renderizar.sh preview\` en macOS/Linux, con Blender instalado. Los perfiles review y delivery ofrecen mayor resolución.
3. Vuelve a **Entregar → Escena para Blender → Revisar render…**. Elige primero el manifiesto original del ZIP, luego \`resultados/preview\`. El diálogo identifica los archivos esperados, muestra la comparación de cámaras cuando existe referencia y explica diferencias de iluminación, texturas y cámaras derivadas.
4. Si quieres firmar, elige una identidad de Mi estudio. **Preparar entrega → Descargar entrega (ZIP)** genera originales íntegros, copias de presentación, informes con huellas y comparación cuando está disponible. Las copias firmadas usan el nombre y el logo escogidos. La selección de firma de esta entrega es temporal.

- Reutiliza captura OP-10, las primitivas ZIP, la marca de Mi estudio y el compositor FloorPlanDeliveryImage. Continúan separados la observación visual del visor y el proyecto canónico. La referencia de identidad local del proyecto no declara revisión F0 confirmada. La API canónica de captura mantiene el contrato de exportaciones repetibles, incluido el caso de GLB retrasado.

Los resultados deben coincidir con el manifiesto original elegido, el proyecto, la revisión observada, la planta y la reapertura del mismo preparado. Se comprueban PNG decodificables, tamaño, huellas y lista completa de vistas. Una discrepancia impide producir la entrega y muestra el siguiente paso. SHA-256 aporta trazabilidad e integridad entre archivos. Una persona que controle todos los archivos puede fabricar un conjunto nuevo.
- En el equipo local, Blender resuelve rutas absolutas y registra la memoria cuando el sistema ofrece la medición. La ejecución identifica los insumos, el script y los parámetros de render. El bloqueo de sistema evita que dos procesos escriban en la misma salida. La reanudación reutiliza PNG verificados y conserva \`review.blend\`, incluidas ediciones de la persona. Las imágenes finales y los informes tienen publicación por archivo.
- Las cámaras interiores derivadas se mantienen dentro de la estancia, con el ojo despejado, verticales rectas y prioridad de encuadre del mueble principal. Se favorece un primer plano despejado. La cámara explícita de RUBIK conserva su pose. La escena no modifica muros, muebles ni materiales guardados.
- Los tres scripts que usan \`bpy\` se distribuyen bajo GPL-3.0-or-later con aviso y texto íntegro en el kit. El ZIP de cliente es diferente del kit ejecutable. El archivo \`.blend\` queda en la máquina del profesional.
