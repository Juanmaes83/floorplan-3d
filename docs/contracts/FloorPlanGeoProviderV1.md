# FloorPlanGeoProviderV1 — contrato runtime territorial

**Versión:** `FloorPlanGeoProvider.CONTRACT_VERSION = '1.1.0'`. Es la versión runtime del contrato; no es versión de ProjectV1, BuildingV1 ni de Catastro. Añade `parcel` como segunda operación completa y conserva la API Manual de 1.0.0. Implementación en `js/geo-provider.js`, `js/parcel-core.js`, `js/catastro-parcel-provider.js` y adapters durables separados.

## Adapter y descriptor

Un adapter declara `id`, `getCapabilities()` y `getProviderMetadata()`. Para `coordinates: true` implementa `getCoordinates(input, context?)`; para `sourceMetadata: true` implementa `getSourceMetadata()`. `inspectProvider(provider)` valida atómicamente el adapter y devuelve un snapshot independiente. Un ID debe ser estable, no vacío y de hasta 80 caracteres. La metadata identifica al adapter/fuente en general; no se confunde con la procedencia de un resultado concreto.

El descriptor normalizado incluye `providerId`, `contractVersion`, `label`, `kind` (`manual`, `official`, `commercial`, `other`), `network` (`none`, `optional`, `required`), `capabilities` y `license.status` (`not-applicable`, `unknown`, `verified`, `restricted`). Puede incluir `sourceName`, `sourceUrl`, `version`, `edition`, `region`, `coverage`, `attribution`, `parcelInputModes` cuando `parcel:true` y datos opcionales de licencia (`name`, `url`, `note`). Los URL de metadata deben ser HTTP(S). `official` no implica reutilización autorizada; `verified` exige evidencia externa y no se infiere.

Las ocho capabilities iniciales son exactamente `search`, `parcel`, `geometry`, `coordinates`, `sourceMetadata`, `orthophoto`, `elevation`, `terrain`, todas booleanas. Son declaraciones de adapter, no garantía de disponibilidad de un dato. `coordinates` y `parcel` tienen operación, validador y resultado completo. Los payloads de las demás capacidades quedan para cortes posteriores.

## Parcela territorial fuente — 1.1.0

Un adapter con `parcel:true` implementa `getParcel(input,context?)` y declara `parcelInputModes` no vacío con `document` y/o `reference`. Sin capability, el registry devuelve `unsupported/capability-disabled` sin invocar; sin modo, `unsupported/parcel-input-mode-disabled`. Un documento entra como `{mode:'document',text,reference?}`; el core no recibe `File` ni `Blob`. La referencia opcional selecciona inequívocamente una parcela si hay varias. Se admiten entradas de 14, 18 y 20 caracteres alfanuméricos, normalizadas a los primeros 14 según la documentación oficial; sólo se eliminan espacios y guiones visuales.

El resultado disponible separa `parcel:{reference,inspireId?,sourceCrs,sourceGeometry,frame}` de `provenance`. `sourceGeometry` es `MultiPolygon` con `polygons[].rings[]`: primer anillo exterior, siguientes huecos, vértices `[x,y]` en CRS fuente, sin cierre duplicado. Se validan anillos, huecos y solapes; se canonicalizan sentido, vértice inicial y orden, sin simplificar ni redondear coordenadas fuente. El `frame` usa el centro del bounding box como origen, unidades metros, X este e Y norte. `toLocalGeometry()` produce milímetros derivados con Y hacia abajo sólo para vista previa; no coloca el edificio ni se persiste.

`catastro-inspire-cp` declara sólo `parcel` y `sourceMetadata`; su único modo activo es `document`, con `network:'none'`. La consulta WFS por referencia **no está habilitada**: el recorrido Chromium→HTTPS→WFS/CORS no pudo verificarse. La documentación oficial consultada el 28-10-2026 publica ejemplos WFS HTTP y una licencia que permite uso propio pero restringe la difusión de datos originales sin transformación. Descriptor y procedencia durable conservan `license.status:'restricted'`, nombre, URL y atribución DGC; no afirman licencia libre ni certificación jurídica. Fuentes: [WFS CP](https://www.catastro.hacienda.gob.es/webinspire/documentos/inspire-cp-WFS.pdf), [licencia INSPIRE](https://www.catastro.hacienda.gob.es/webinspire/documentos/Licencia.pdf), [GML de parcela](https://www.catastro.hacienda.gob.es/ayuda/informacion_kml_fxcc_gml.htm) y [CRS oficiales](https://www.catastro.hacienda.gob.es/es-ES/asistente_catreg.html).

El parser usa `DOMParser` XML con namespace URI + nombre local, rechaza DOCTYPE, DTD/entidades y documentos mal formados. Limita el documento a 2 MB, 32 parcelas, 4000 puntos, 64 polígonos y 128 anillos: son defensas de rendimiento, no límites oficiales catastrales. Soporta `MultiSurface`, varios miembros y huecos; no elige la primera parcela si hay varias. Sólo acepta CRS métricos oficiales `EPSG:25829`, `25830`, `25831`, `32628`; CRS geográficos o Web Mercator dan `unsupported-source-crs` sin reproyección.

## Registry y resultados

`createRegistry(initialProviders?)` crea un registry aislado con `register`, `unregister`, `has`, `get`, `inspect`, `list({capability})`, `getCoordinates(providerId,input,context?)` y `getParcel(providerId,input,context?)`. `createDefaultRegistry()` incorpora `Manual` y `catastro-inspire-cp` limitado a documento local. No existe singleton mutable ni selección automática del primer provider. `get()` entrega la referencia al adapter registrado a código runtime de confianza; `inspect()` y `list()` entregan copias independientes ordenadas por `providerId`. El registro duplicado o inválido falla sin modificar el registry. La UI filtra `list({capability:'parcel'})` sin bifurcar por nombre de fuente.

La invocación normalizada es asíncrona para admitir adapters futuros. Todos los resultados incluyen `status` y `providerId`; los no disponibles incluyen `reason` estable. Estados del contrato: `available`, `not-found`, `unavailable`, `invalid`, `unsupported`, `cancelled`. Un ID omitido da `invalid/invalid-provider-id` con `providerId:null`; un ID desconocido da `not-found/provider-not-registered`. Si el adapter responde que no halló coordenadas, se normaliza como `not-found/coordinates-not-found` sin exponer detalles privados. Capability desactivada da `unsupported/capability-disabled` sin invocar; error o resultado defectuoso da `unavailable/provider-error` sin exponer stack; entrada inválida conserva códigos de campo `coordinates` o `timeZone`; un `AbortSignal` ya abortado da `cancelled/cancelled` antes de invocar. No hay retry, timeout, caché ni transporte de red.

Para coordenadas se aceptan únicamente latitud numérica finita entre −90 y 90, longitud numérica finita entre −180 y 180 y zona IANA reconocida por `Intl`. El resultado disponible contiene `location:{latitude,longitude,timeZone}` y `provenance:{providerId,type,...}`. La procedencia del resultado admite sólo los campos durables existentes `sourceName`, `sourceUrl`, `sourceId`, `retrievedAt`, `version`, `derivedFrom` cuando realmente existen; no se inventa `retrievedAt`. No se producen altitud, dirección, municipio, parcela, precisión ni radio de exactitud.

`Manual` conserva `id`, `capabilities`, `getCoordinates()` y `getSourceMetadata()` originales. Su descriptor declara `network:'none'` y `license.status:'not-applicable'`. La llamada directa antigua sigue entregando `location.source:{providerId:'manual',type:'user-entered'}`; el registry la convierte en el envelope normalizado. Los campos ajenos de input no viajan al resultado.

## Frontera con site y persistencia

`FloorPlanGeoSiteAdapter.toSiteLocation(result)` acepta sólo coordenadas normalizadas `available` y construye exactamente `site.location:{latitude,longitude,timeZone,source}`. `fromSiteLocation(siteLocation)` lee y valida un dato durable sin registrar, buscar ni contactar al provider. Conserva procedencia soportada, no muta entradas y no persiste descriptor, capabilities, modo de red, objeto provider, licencia runtime ni respuesta completa. El descriptor de licencia/atribución general permanece runtime; **no se afirma que toda esa metadata esté guardada en `site.location.source`**.

La autoridad sigue siendo `project.site`; en edificios, **`building.site`**. `level.project.site` no es fallback territorial. Un documento con un `source.providerId` ausente sigue siendo válido y portable. `FloorPlanParcelSiteAdapter` convierte el resultado disponible en `site.parcel` y lo reconstruye sin provider; persiste geometría fuente validada, frame y snapshot de procedencia legal, nunca XML bruto, respuesta HTTP o geometría local derivada. ProjectV1 1.9.0 y BuildingV1 1.2.0 admiten este campo; abrir documentos anteriores no los migra. PNG, GLB, Blender, fichas, presentación y vídeo no incluyen la parcela automáticamente.

Geometría fuente de un provider **no equivale** a geometría editable del proyecto: una conversión futura exigirá un adapter/proceso explícito. 8C-C queda para ortofoto/contexto; 8C-D para elevación/terreno; 8C-E para integración final. Este contrato no garantiza cobertura territorial, exactitud, derecho de reutilización, disponibilidad de red ni representación editable.
