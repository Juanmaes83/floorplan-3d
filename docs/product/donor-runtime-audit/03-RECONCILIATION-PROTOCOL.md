# Reconciliation protocol

For each **observed milestone**, proceed in this order:

`OBSERVED_RUNTIME → DONOR_SOURCE → CUT_ATLAS → RUBIK_CURRENT → GAP → BRIDGE_CANDIDATE → DEPENDENCIES`.

Begin with what changed in Mxx, what remained continuous, and the professional problem/outcome. Trace donor file, symbol, state, progress mapping, camera, geometry, visibility, material/shader, lighting, scroll listener and lifecycle including reverse/cleanup. Classify each source link `SOURCE_CONFIRMED`, `SOURCE_PARTIAL`, `SOURCE_ADJACENT` or `SOURCE_NOT_FOUND`; adjacent code is not causal proof.

For each Dxx/Cut/Atlas statement record `CONFIRMS`, `EXTENDS`, `CONFLICTS`, `NOT_APPLICABLE` or `UNRESOLVED`. Keep Cut 5 completion precedence. Record divergence in `conflicts.json`; do not rewrite a Cut.

Only then inspect Rubik at approved SHA in this order: semantic/project authority, geometry, representation, materials/light, camera, transition, scroll/progress, UI, mobile, lifecycle/restore, outputs, QA. Complete exactly 12 crosswalk dimensions. `EXISTS` and `PARTIAL` require exact Rubik locators; `MISSING` requires a bounded capability claim, not absence of a donor label. Status values: `EXISTS`, `PARTIAL`, `MISSING`, `NOT_APPLICABLE`, `UNRESOLVED`.

Gap values: `NO_GAP`, `INTEGRATION_GAP`, `ORCHESTRATION_GAP`, `REPRESENTATION_GAP`, `TRANSITION_GAP`, `CAMERA_CHOREOGRAPHY_GAP`, `MATERIAL_LIGHT_GAP`, `INTERACTION_GAP`, `MOBILE_GAP`, `LIFECYCLE_GAP`, `OUTPUT_GAP`, `QA_GAP`, `MISSING_CAPABILITY`, `PRODUCT_DECISION_REQUIRED`, `DONOR_LIMITATION`, `UNRESOLVED`. Check integration and orchestration before declaring missing.

Bridge values: `REUSE_EXISTING`, `CONNECT_EXISTING`, `ADAPT_EXISTING`, `REIMPLEMENT_MECHANISM`, `REFERENCE_ONLY`, `DEFER`, `REJECT`, `UNRESOLVED`. Each bridge records problem, Rubik authority preserved, existing capabilities used, missing connector, donor mechanism reference, confidence, and `implementationAuthorized: false`. Preserve existing Global/Cut disposition or explain divergence; do not implement.

Evidence classes are `OBSERVED_RUNTIME`, `DONOR_SOURCE`, `CUT_ATLAS`, `RUBIK_CURRENT`, `INFERENCE`. An inference stores statement, supporting evidence and unresolved/confirmed status. It cannot alone satisfy a hard gate. Unknowns are `BLOCKING` or `NON_BLOCKING`, with attempts and required evidence. Hidden unknowns are unacceptable.

REA is used only after Cuts, runtime and donor source leave an exact technical question. Log question, insufficiency, take, mechanism and expected evidence; result `REA_RESOLVED`, `REA_PARTIAL`, `REA_NO_ADDITIONAL_EVIDENCE` or `REA_CONFLICT`. REA is auxiliary, never product authority.

Conflicts use the five types and severity/status enums in the schema. Shared mechanisms and dependency graph describe technical reuse and prerequisites, separately from professional service identity. Graph edges do not set implementation order. Derive future QA invariants under SEMANTIC, GEOMETRY, VISUAL, CAMERA, LIFECYCLE, MOBILE, ACCESSIBILITY, OUTPUT, REGRESSION. No product test implementation in this mission.
